# PM Company Website - Project Memory

## Project Overview

This project is a premium marketing website for a project management company.

The goal is to create a website that inspires confidence in executives, government agencies, NGOs, and corporate clients looking for professional project management services.

The website should communicate:
- Professionalism
- Trust
- Expertise
- Reliability
- Premium quality

Every design and development decision should support these goals.

# Design Philosophy

This is NOT a startup website.

This is NOT a SaaS dashboard.

This is NOT a trendy portfolio.

This is an executive corporate website.

The design language should feel similar to premium consulting firms.

Characteristics:

- Clean
- Spacious
- Confident
- Modern
- Minimal
- Executive
- Premium

Avoid:
- excessive gradients
- flashy animations
- childish icons
- oversized buttons
- clutter

Whitespace is part of the design.

# User Experience Principles

Every page should answer:

Who are we?

What do we do?

Why should someone trust us?

How do they contact us?

Navigation should always feel effortless.

---

# Accessibility

Accessibility is mandatory.

Requirements:

- WCAG AA contrast
- Semantic HTML
- Proper heading hierarchy
- Keyboard navigation
- Visible focus states
- Accessible forms
- Alt text where appropriate

Never sacrifice accessibility for aesthetics.

---

# Responsive Design

Desktop first impression must feel premium.

Tablet should maintain spacing.

Mobile should prioritize readability.

No horizontal scrolling.

---

# Components

Components should remain reusable.

Avoid duplication.

Prefer composition over repetition.

Keep business data separated from UI.

---

# Animations

Animations should feel subtle.

Purpose:
- improve clarity
- improve perceived quality

Never distract the user.

---

# Security

Never expose secrets.

Never hardcode credentials.

Validate user input.

# Claude Guidelines

Before making large changes:

Explain the approach.

Preserve existing architecture.

Respect existing design language.

Avoid unnecessary rewrites.

If unsure, ask.

Do not introduce breaking changes without a clear reason.
